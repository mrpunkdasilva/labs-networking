Atividade #1 - Análise do Three-Way Handshake (Observabilidade)

Nesta atividade, observamos o processo de estabelecimento de uma conexão TCP (Three-Way Handshake) em um ambiente Fedora Linux, analisando tanto o acesso a um serviço HTTP quanto um caso prático de transferência de arquivos.

Ferramentas Utilizadas

  • curl / wget: Para gerar tráfego de rede e realizar transferência de arquivos.

  • Wireshark: Para captura e análise visual dos pacotes.

  • Shell (Bash): Ambiente de execução dos comandos no Fedora.

Passo a Passo da Execução

1. Preparação da Captura

Iniciamos o Wireshark e selecionamos a interface ativa (wlo1). Aplicamos o filtro inicial para capturar o tráfego TCP nas portas de interesse.

  • Filtro: tcp.port == 443 or tcp.port == 80

2. Caso Prático: Transferência de Arquivos

Para testar a conexão em um cenário real de transferência de dados, utilizamos o comando wget para baixar um arquivo de teste de um servidor público.

wget https://proof.ovh.net/files/1Mb.dat

3. Filtragem e Análise Avançada

Para isolar precisamente apenas os pacotes de controle que formam o "aperto de mão", aplicamos um filtro lógico avançado no Wireshark.

  • Filtro Utilizado: tcp.flags.syn == 1 or (tcp.seq == 1 and tcp.ack == 1 and tcp.len == 0)

Explicação do Filtro:

  • tcp.flags.syn == 1: Captura pacotes com a flag SYN ativa, o que abrange a primeira fase (SYN) e a segunda fase (SYN-ACK) do handshake.

  • tcp.seq == 1 and tcp.ack == 1 and tcp.len == 0: Identifica o terceiro pacote (ACK) da negociação, que possui número de sequência 1, confirmação 1 e não transporta dados de carga (payload).

Análise das Três Fases (SYN, SYN-ACK, ACK)

Através da inspeção detalhada do cabeçalho TCP (como visto na imagem acima para o pacote No. 1501), identificamos as fases conforme exigido:

  1. SYN (Synchronize): O pacote inicial enviado pelo cliente (Flags: 0x002 (SYN)). Na captura, observamos o campo Flags destacando o bit SYN como ativo, propondo a abertura da conexão.

  2. SYN-ACK (Synchronize-Acknowledge): O servidor responde confirmando o recebimento (Acknowledgment Number: 1) e enviando seu próprio bit SYN ativado.

  3. ACK (Acknowledge): O pacote final enviado pelo computador local. Este pacote completa a negociação, movendo o estado da conexão para ESTABLISHED.

Conclusão

O teste prático e a posterior filtragem avançada no Wireshark permitiram comprovar a robustez do protocolo TCP. A capacidade de isolar bits específicos do cabeçalho (Flags) demonstra como o sistema garante que a transferência de arquivos (como o download de 1MB realizado) só comece após uma negociação de três vias bem-sucedida e confiável.
